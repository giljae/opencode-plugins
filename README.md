# opencode-plugins

Unofficial [OpenCode](https://opencode.ai) V2 plugins and skills, published to
npm under the [`@giljae`](https://www.npmjs.com/org/giljae) scope. This is a
monorepo: one publishable OpenCode plugin per package, sharing tooling for
upstream sync, verification, and release.

These packages are not affiliated with or endorsed by OpenCode or with the
upstream projects they adapt.

## Plugins

| Package | Description | Install |
|---------|-------------|---------|
| [`@giljae/opencode-egm`](https://www.npmjs.com/package/@giljae/opencode-egm) ([source](packages/opencode-egm)) | An OpenCode port of [Elephant-Goldfish Model](https://github.com/google/elephant-goldfish-model): develop an idea with context, review it with fresh eyes. Adds an `egm` orchestrator, eight read-only reviewer subagents, seven skills, and seven `/egm-*` commands. | `opencode plugin add @giljae/opencode-egm` |
| [`@giljae/opencode-postgres-skills`](https://www.npmjs.com/package/@giljae/opencode-postgres-skills) ([source](packages/opencode-postgres-skills)) | An OpenCode port of [microsoft/postgres-skills](https://github.com/microsoft/postgres-skills): PostgreSQL guidance, Apache AGE graphs, and Oracle migration, plus a local `postgres-mcp` MCP server. | `opencode plugin add @giljae/opencode-postgres-skills` |

New plugins are added to this table as they land.

## Repository layout

```
packages/
  <plugin>/            one publishable OpenCode plugin per directory
scripts/
  sync-upstream.mjs    vendor an upstream release tag with provenance
  lib/sync-core.mjs    hashing and drift helpers
  verify-plugin.mjs    offline check: agents discovered, reviewers read-only
docs/
  superpowers/         design and implementation notes
  verification/        what was verified on a real OpenCode, and what was not
```

## Using a plugin

Every plugin is published on npm under the
[`@giljae`](https://www.npmjs.com/org/giljae) scope, so you install it by name:

```sh
opencode plugin add @giljae/<plugin>
```

`opencode plugin add` fetches the package from the npm registry and adds it to
your OpenCode configuration, so the plugin applies in every project. You can
also install a package directly with `npm install @giljae/<plugin>` when you
load plugins by path instead of by name.

Plugins are OpenCode V2 server plugins. Individual plugins document any extra
setup they need (for example, EGM installs its agent files with an in-OpenCode
command, because OpenCode V2 plugins cannot add agents).

## Developing

Requires Node 20 or newer.

```sh
npm install        # install workspaces
npm test           # run every package's tests
npm run typecheck  # typecheck every package
npm run sync -- --ref vX.Y.Z   # vendor a new upstream tag (maintainers)
```

Each package follows the same shape:

- `src/index.ts` exports the `Plugin.define` server part, pointed at by the
  package's `exports`.
- Tests live in `test/` and use fakes for the OpenCode context, so they run
  without a model.
- Vendored third-party content, when present, lives under `vendor/` and is
  generated by a sync script with a recorded upstream commit; never edit it by
  hand.

Adding a plugin means creating a directory under `packages/`, following the
shape above, and adding a row to the plugin table.
